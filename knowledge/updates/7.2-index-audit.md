## 节点索引

- 当前 1294 条节点索引，与按现行生成规则复算的结果一致；源路径及输出路径均有效。
- 输入 1295 个节点块，现有 `(title, whitespace-normalized content)` 去重仅合并 1 个。标题含转义编号、不同图片 URL 会使同一功能保留多份。
- 同一输出文件内存在 244 组同名标题，多出 412 条记录。
- `backend/skill/service.py` 的 `_parse_chunks_from_md` 使用 `chunks[title]` 保存正文，后面的同名块覆盖前面的块；`_lookup_node_matches` 又按标题查正文。因此 412 条索引记录获取的 Markdown 与其原始块不一致。
- 排除图片 URL 和归属端标签后，仍有 20 条正文差异，包含措辞和实际参数差异。不能将 412 条全部解释为功能错误，也不能将其全部安全合并。
- 去除编号、图片并折叠空白后，有 202 组内容相同候选，多出 529 条；这是候选统计，图片含义、上下文和端归属还需核验。
- 公开 API 已复现：查询“获取自身当前执行状态”返回两个不同来源，但正文均取后一个来源。更明显的“获取射线检测结果”在来源间存在检测发起者类型（枚举/实体）与输出（是否命中实体/命中实体）差异，当前查询会覆盖其中一个版本。

## 修复优先级

1. 为节点块建立稳定唯一标识，查询按块 ID 取正文，避免同名覆盖；保留来源和端归属。
2. 在保留真实功能/参数差异的前提下，规范标题编号、合并确认相同的节点，并保留所有来源。
3. 爬虫落盘按文档 ID 清理旧标题文件；导入按 ID 选择有效版本，移除 4 个旧源文件。
4. 排除 README/category 等说明文件和空块；核对 BBS 楼层唯一性，处理第 902 楼重复；对公共模板切片制定过滤规则。
5. 备份后定向更新 RAG 与派生索引，再验证查询结果、节点数和过滤范围。
